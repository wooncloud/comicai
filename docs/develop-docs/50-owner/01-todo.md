## 1. 플랫폼 AI 키 — 이게 없으면 나머지가 무의미하다

`.env` 의 `PLATFORM_GEMINI_KEY` 에 Google AI Studio 키를 넣는다.

**왜.** 지금은 사용자 키를 찾고(없음) → 플랫폼 키를 읽고(빈 값) → 실패한다. 화면에는
"지금은 그림을 만들 수 없습니다. **잠시 후 다시 시도해 주세요**" 가 뜬다. 기다리면 풀린다는
뜻이라 사용자는 계속 다시 누르고, 영원히 안 된다. 가입 시 20토큰을 줘도 쓸 데가 없다.

우회로도 없다. 사용자가 자기 키를 넣는 기능(BYOK)은 `FEATURE_API_KEYS` 가 꺼져 있어
화면·API 둘 다 404다.

**주의.** 사용자가 고를 수 있는 모델이 Gemini·OpenAI 두 개다. Gemini 키만 넣고 열면
OpenAI 를 고른 사용자는 똑같이 영원히 실패한다. 둘 중 하나만 쓸 거면
`apps/web/lib/model-options.ts` 에서 나머지 모델을 빼 달라고 하면 된다.

```
PLATFORM_GEMINI_KEY=AIza...
```

넣은 뒤 `api`·`worker` 재기동. `.env` 의 `GEMINI_API_KEY` 는 랜딩 샘플 생성 스크립트
전용이라 렌더에 쓰이지 않는다 — 헷갈리지 말 것.

## 2. 관리자 계정 만들기 — 안 하면 돈을 받아도 토큰을 못 준다

`ADMIN_EMAILS` 는 이미 채워져 있다. 남은 건 **그 주소로 가입하고 이메일 인증을 마치는 것**.

**왜.** 이름이 목록에 있는 것만으로는 관리자가 아니다. `emailVerifiedAt` 이 없으면 무조건
403이다. 저장소가 공개라 운영자 이메일이 git 기록에 보이는데, 인증을 안 걸면 그 주소를
아는 사람이 먼저 가입해 관리자 자리를 선점할 수 있어서 일부러 그렇게 돼 있다.

지금 62명 중 **인증을 마친 계정이 0명**이다. 즉 `/admin` 에 아무도 못 들어간다. 그런데
`/admin` 의 "입금 확인" 버튼이 **결제를 완결시키는 유일한 경로**다.

**방법.** 그 이메일로 가입 → 인증 메일 링크 클릭. 3번(RESEND)을 아직 안 했다면 메일이
안 오므로, `docker logs comicai-api` 에서 `[email] to=… /verify-email/<토큰>` 링크를 찾아
브라우저에 붙여 넣으면 된다. `ADMIN_EMAILS` 를 바꿨다면 api 재기동 필수(기동 시 1회만 읽는다).

## 3. `RESEND_API_KEY` — 메일이 나가야 하는 이유

**왜.** 지금은 인증 메일·비밀번호 재설정 메일이 서버 콘솔에만 찍힌다. 사용자는 가입 후
인증을 못 하고, 비밀번호를 잃으면 되찾을 방법이 없다. 2번의 우회로(도커 로그)는 사장님
본인 계정에만 쓸 수 있다.

`https://resend.com` 에서 발급 → `RESEND_API_KEY=` 에 넣는다.
`EMAIL_FROM` 은 지금 Resend 테스트 주소(`onboarding@resend.dev`)라, 도메인을 붙이면
같이 바꾼다.

## 4. 외부 접속 — Cloudflare 터널

`CLOUDFLARE_TUNNEL_TOKEN` 이 비어서 `cloudflared` 가 계속 재시작 중이다(확인함).

**왜.** web(3000)·api(4000) 를 포함한 모든 포트가 `127.0.0.1` 에만 열려 있다. 외부에서
들어올 유일한 통로가 이 터널이다. 서버에서 `curl localhost` 는 되는데 폰에서는 사이트가
안 열리는 상태다.

**방법.** Cloudflare Zero Trust 에서 터널을 만들고 토큰을 `.env` 에 넣는다.
대시보드의 public hostname 은 **도커 네트워크 이름**(`http://web:3000`, `http://api:4000`)을
가리켜야 한다 — `host.docker.internal` 이면 루프백 바인딩 때문에 안 닿는다.

### 4-b. 도메인이 붙으면 같이 바꿀 값 네 개

`comicai-deploy/.env` 의 아래 넷이 전부 `localhost` 다. 도메인으로 열면 네 가지가 **동시에**
깨지는데 서버 로그는 깨끗하고 `healthz` 도 정상이라 원인을 못 찾는다.

| 값                    | 안 바꾸면                                                                             |
| --------------------- | ------------------------------------------------------------------------------------- |
| `WEB_ORIGIN`          | CORS 가 localhost 만 허용 → 브라우저가 **모든 API 호출 차단**. 로그인조차 안 됨       |
| `NEXT_PUBLIC_API_URL` | 웹이 localhost 로 API 를 부른다. **빌드 시점에 박히므로 `--build` 재빌드 필수**       |
| `API_PUBLIC_URL`      | OAuth 콜백 주소가 틀려 소셜 로그인 실패                                               |
| `S3_PUBLIC_ENDPOINT`  | 이미지·내보내기 다운로드 링크가 `localhost:9000` 으로 서명됨 → **결과물을 못 받는다** |

## 5. 토큰 판매 켜기 — `BILLING_NOTICE`

**왜.** 비어 있으면 서버가 충전 주문을 **거부**한다. 일부러 그렇게 만들었다 — 어디로 얼마를
보낼지 말해 줄 수 없으면 주문을 받아 봐야 사용자가 다음에 할 일이 없고, 그건 버튼이 없는
것보다 나쁘다(성공한 것처럼 보인다).

```
BILLING_NOTICE=국민 123456-78-901234 (예금주 홍길동) 로 입금 후 주문번호를 회신해 주시면 확인 뒤 지급합니다.
```

채우면 `/settings/billing` 에 "충전 요청" 버튼이 생기고, 사용자가 **입금자명**과 함께 요청을
남긴다. 그 뒤 운영은 이렇다:

1. 통장에 입금 확인 (이름 + 금액)
2. `/admin` 상단 "입금 확인 대기" 에서 같은 이름·금액 줄을 찾는다
3. "입금 확인" 클릭 → 토큰이 즉시 들어간다

**PG 는 아직 없다.** 이게 파는 방법의 전부다. 하루 몇 번 볼지 정해 두는 게 좋다.

### 5-b. 켜기 전에 정할 것

- **가격**: 지금 50토큰 5,000원 / 120토큰 10,000원 / 700토큰 50,000원. 단가는 Gemini 1토큰,
  OpenAI 4토큰, 가입 지급 20토큰. **바꾸려면 코드 수정 + 배포가 필요하다** — 시작가를
  신중히 정할 것.
- **환불 정책**: 약관에 환불 조항이 없다. 이미 지급된 주문을 되돌리는 수단은 `/admin` 의
  토큰 회수뿐이다.

## 6. 법적 문서 — 돈을 받기 전에

### 6-a. 자리표시자 채우기

`/terms` 와 `/privacy` 하단에 `[운영 주체명]`·`[담당자명]`·`[문의 이메일]` 이 그대로 있다.

파일: `apps/web/app/(legal)/terms/page.tsx`, `apps/web/app/(legal)/privacy/page.tsx`

**특히 `[문의 이메일]` 은 실제로 수신되는 주소여야 한다.** 처리방침이 "계정 삭제는 아래
문의처로 요청해 주시면 처리해 드립니다" 라고 약속하는데, 화면에 탈퇴 버튼이 없어서
**그 주소가 이용자의 유일한 삭제 요구 경로다.** 지금은 자리표시자라 경로가 0개다.
요청이 오면 계정을 지우는 절차도 정해 둬야 문장이 사실이 된다.

### 6-b. 약관을 유료 서비스 기준으로 다시 쓰기

- §5 가 아직 "계정마다 하루 생성 횟수에 상한이 있습니다" 라고 한다 — **이미 거짓이다.**
  하루 상한은 토큰제로 바뀌면서 삭제됐다.
- 목차 9개 어디에도 **결제·환불·청약철회 조항이 없다.**

돈을 받기 시작하는 순간 이 문서는 사실과도 다르고 법적으로도 비어 있다.

### 6-c. 사업자 정보

유료 충전을 켜면 상호·대표자·사업자등록번호·주소 표기 위치를 정해야 한다.

## 7. 보안 — 데이터가 쌓이기 전에

`POSTGRES_PASSWORD` · `MINIO_ROOT_PASSWORD` 가 **`.env.example` 의 공개 기본값과 문자 하나까지
같다**(`comicai` / `minioadmin`). 저장소가 공개라 누구나 안다.

지금은 포트가 `127.0.0.1` 에만 열려 있어 인터넷에서 바로 닿지는 않지만, 서버에 들어오는
누구든 DB 전체(이메일·비밀번호 해시·암호화된 API 키)와 스토리지 전체를 가져간다.
**나중에 바꾸려면 볼륨과 자격증명을 함께 회전시켜야 해서 훨씬 비싸다.**

```
node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
```

로 두 개 만들어 넣고, `DATABASE_URL` 안의 비밀번호도 같이 고친다.

그리고 **`MASTER_KEY` 는 비밀번호 관리자에 따로 보관하라.** 백업은 `.env` 를 일부러
저장하지 않는다(외부 저장소가 뚫리면 전부 뚫리므로). 잃으면 사용자가 저장해 둔 BYOK 키만
못 읽고 재입력하면 되지만, 그 외 값은 전부 다시 만들 수 있다.

## 8. 백업 — 지금은 반쪽이다

돌고는 있는데(컨테이너 확인함) **원본과 같은 디스크에 쌓인다.** 디스크가 죽으면 DB·오브젝트·
백업이 함께 죽는다.

- **`BACKUP_REMOTE_ENDPOINT` / `_ACCESS_KEY` / `_SECRET_KEY` / `_BUCKET`** 을 채우면 매 회차
  끝에 외부 S3 로 밀어낸다. 목적지는 사람이 정해야 해서 기본값을 둘 수 없다.
  (더 약한 대안: `BACKUP_HOST_PATH` 에 다른 디스크/NAS 마운트 경로)
- **`BACKUP_WEBHOOK_URL`** 을 채우면 실패를 Slack/Discord 로 던진다. 안 채우면 알아채는
  경로가 `docker ps` 의 `unhealthy` 표시뿐인데, 그걸 누가 언제 볼지 정해 둬야 한다.
- **복구 리허설을 한 번 해라.** 만드는 코드는 3중 검증까지 돼 있는데 **되돌리는 절차가
  코드에도 문서에도 없다**(저장소에 `pg_restore` 0건). 한 번도 풀어 본 적 없는 덤프는
  백업이 아니라 백업처럼 생긴 파일이다. 한가한 날 스테이징에서 한 번 돌려 보고, 걸린
  시간과 명령을 `docs/05-infra-ops.md` 에 적어 두면 그게 런북이다.
